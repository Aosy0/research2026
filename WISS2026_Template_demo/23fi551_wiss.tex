\begin{abstract}
	データを物理的な形状や物体として表現する「Data Physicalization」は，
	データの理解や探索を支援する手法として研究が進められている．
	なかでも都市データの物理化は，実際の街の構造を立体模型として表現する手段となる．
	国土交通省のProject PLATEAUでは，建物・地形を含む高精度な3D都市モデルが公開されている．
	しかし，これらを3Dプリントして立体模型として利用するには，地形に厚みを付与するとともに，
	建物と地形を印刷可能な閉じたメッシュとして統合する必要がある．
	そこで本研究では，Web地図上で領域を指定するだけで，
	PLATEAUの建物と地形を統合した3Dプリント用モデル（3MF/STL）
	を自動生成するツールキット「machimoki」を開発した．
	本稿では，WebAssemblyを用いた自動生成機構の設計と実装を示し，
	実際の都市データを用いた生成と，スライス処理の確認結果を報告する．
\end{abstract}

\maketitle

\section{はじめに}
「Data Physicalization」\cite{jansen2015}とは，
データを物理的な形状や物体として表現する研究であり，
地理空間データの物理模型\cite{herman2025,millar2018}も作られている．
これらはいずれも地形データを扱うが，実在する街の模型では地形に加えて建物のデータが必要となる．

そのデータ基盤として，国土交通省の「Project PLATEAU」\cite{plateau}が，
建物・地形を含む高精度な3D都市モデルをオープンデータとして公開している．

しかし，これらを3Dプリント可能な模型とするには，対象領域の抽出と縮尺調整，
底面開口や自己交差といったデータの不備，建物と地形の結合などの課題がある．
このような修正は非専門家には難しく，その複雑さが指摘されている\cite{martial2026}．
筆者らがPLATEAUデータをBlenderで加工して模型を制作した際にも，多くの手間を要した．

地図上で範囲を指定して模型を得るツールとして，
地形モデルを生成するTouchTerrain\cite{hasiuk2017}，
建物と地形を出力する3DcityLoader\cite{3dcityloader}，Mini Skyline\cite{miniskyline}，
Map2Model\cite{map2model}などがある．いずれもOSMや各国のオープンデータ，全球DEMなどを利用している．
これに対し，本研究は日本の都市を対象とし，国土交通省が整備するPLATEAUの建物と地形をモデル化する．

そこで本研究では，Web地図上で領域を指定するだけで，
PLATEAUの建物と地形を統合した印刷可能なメッシュモデルを自動生成するツールキット「machimoki」
を開発した．

\section{システム実装}
machimokiは，frontend，core，workerの3層構成で実装している．

\subsection{フロントエンド（frontend）}
フロントエンドにはJavaScriptライブラリのReactとビルドツールのViteを用い，2D地図にはオープンソースのMapLibre GL，3D地図にはCesiumJS（JavaScriptライブラリ）を用いる．
ユーザーは地理院タイル\cite{gsi}を使用した地図上で，
任意の範囲を矩形選択できる（図\ref{fig:ui}）．
PLATEAUのデータが整備されている範囲をオーバーレイ表示し，データが存在する地域を地図上で確認できる．
選択範囲の建物・地形はCesiumJSにより3D地図として表示され（図\ref{fig:preview}），
模型サイズ，地形底面厚み，底面フラット化などのパラメータをリアルタイムに調整できる．

	\centering

	\caption{machimoki Webインタフェース：PLATEAUカバレッジ表示と地図上の領域選択（地図データ：国土地理院）
	}

\end{figure}

\subsection{3Dモデルの生成（core）}
本ツールの3Dモデル生成では，WebAssembly版の\verb|manifold-3d|\cite{manifold3d}を用いて以下の4段階で処理する．
1)選択範囲の経緯度（WGS84）を中心原点の局所直交座標系（ENU）へ変換する．
2)PLATEAU 3D Tiles（建物群をまとめたタイル形式b3dm）から，3Dモデルの形状・外観を記述するファイル形式glTFのバイナリ版GLBを取り出し，頂点を結合して建物単位に分割した後，底面の開口部を，底面の頂点群をすべて含む最小の多角形でふさぐ．
3)地形タイルからPLATEAUの標高データを格子状にサンプリングし，地表に厚みを与える．このとき，下面を最も低い地表点から厚み分だけ下げた水平面とすることで，平らな底面をもつ地形メッシュを生成する．あわせて，各建物の底面を直下の地形の最低標高へ接地させ，わずかに沈み込ませる補正を行う．
4)建物群と地形メッシュをブール結合（Union）し，自己交差を解消したひとつの閉じたメッシュモデルを構築する．

\subsection{配信・API（worker）}
配信・API層はCloudflare社のサービスCloudflare Workers上に実装し，
Webアプリ本体と，カバレッジタイル（PLATEAUデータの整備状況を示す）を同社のオブジェクトストレージR2から配信する．
通常はブラウザ内（WebAssembly）で処理し，失敗時はフォールバックとして，
workerのAPIが負荷の大きい処理をオリジンサーバ上のcore APIへ中継する．

\section{制作例と検証}
実際の都市データを対象としたモデル生成と検証を行った．

生成したモデルの検査では，オープンエッジ数（面が1枚しか接していない辺の数），非多様体エッジ数（3枚以上の面が接する辺の数），自己交差の有無，接続シェル数（つながった立体の数）を評価する．オープンエッジ数と非多様体エッジ数がいずれも0で，自己交差がなく，接続シェル数が1のときを合格とする．接続シェル数のみが2以上のときはwarning，それ以外は不合格とする．

\begin{figure}[htbp]
	\centering
	\includegraphics[width=0.85\columnwidth]{IMG_6336.jpg}
	\caption{生成モデルを3Dプリントした模型（東京電機大学 千住キャンパス，1/2437）}
	\label{fig:print}
\end{figure}

\subsection{大学キャンパスを対象としたモデル生成}
東京都足立区の東京電機大学千住キャンパスを対象に，machimokiで1/2437（印刷模型は約10cm四方）の
モデルを生成し，3Dプリントした（図\ref{fig:print}）．Web UI上での範囲選択後，数十秒で建物群と
地形が1つのメッシュとして生成された．

\subsection{メッシュ品質検証とスライス適性の確認}
生成したモデルを検証した結果，オープンエッジ数0，非多様体エッジ数0，自己交差はなかったが，
地形タイルの解像度と建物データの標高の不一致により接続シェル数が2となり，warning判定となった．
また，生成した3Dモデルを，表示・解析機能を備えたスライサーソフトウェア（Prusa ResearchのPrusaSlicerとBambu LabのBambu Studio）に読み込んだ．メッシュ破損などのエラーは生じず，積層パスが正常に生成されることを確認した．

\section{まとめ}
本稿では，
PLATEAUの3D都市モデルと地形データから3Dプリント可能な閉じたメッシュモデルを自動生成するツールキット「machimoki」
を開発した．WebベースのUI，manifold-3dを用いたメッシュの生成・結合と検査，
STL/3MF出力を実装し，実際の都市データを用いた検証では，メッシュ検査に加え，スライサー（PrusaSlicer，Bambu Studio）でスライス処理が正常に行えることを確認した．
検証では，地形タイルと建物データの標高の不一致による接続性の改善が課題として残った．
今後は，この改善に加え，既存ツールとの比較や，中空化機能・電子部品配置ソケットの生成，IoTデバイス連携を進める．
\label{bodyend}

\section*{謝辞}
本研究では，国土交通省の「Project PLATEAU」が公開する3D都市モデルを加工して利用した．また，
背景地図に国土地理院の地理院タイルを使用した．さらに，UIの施設検索にはOpenStreetMapのデータを利用した．ここに記して謝意を表する．
